# 产品需求与实现范围

## 用户与目标

面向持有Rokid眼镜、拥有个人麦当劳MCP授权的用户。通过语音提出点餐意图，眼镜显示必要选择和金额，用按键完成敏感提交。此公开版本面向单账号本地体验，不声称已完成生产多用户隔离。

## 主流程

1. 首页唤醒后解析每种餐品、数量和就餐方式；缺失方式时询问，但保留需求。
2. 自取定位并查询门店，配送选择地址；不自动替用户选择门店。
3. 查询门店真实菜单，按需求逐项匹配。唯一明确匹配打开详情，歧义进入每批最多5项的列表。
4. 规格和数量均依据真实返回；用户加购后才推进下一项，支持跳过。
5. 购物车支持行删除、整车清空及最近一次撤销；其他编辑或离开流程后撤销失效。
6. 按商品编码匹配可用券，无匹配则跳过；默认无需餐具、立即安排和打包，已有明确预约保留。
7. 实时算价并核对取餐方式。语音可以修改偏好，最终创建订单必须按确认键。
8. 支付在手机完成；眼镜查询订单状态，历史订单从列表直达详情。

## 必须保持的约束

- 真实产品编码、价格、可售性、优惠和取餐方式来自MCP，不能靠模型猜测。
- 最终写操作必须由当前确认页按键触发；不确定结果先核实，不自动重试。
- 每次进入支持页面监听一次，最长15秒和最多3秒最终结果等待；离页与隐藏释放麦克风，忽略迟到结果。
- 首页需唤醒，不持续拾音；应用自身不播报TTS。
- 结算重新核验，不以菜单参考价冒充商品小计；无法可靠对应时明确待核实。
- 菜单精简是本地展示优化，不承诺缩短上游请求时间。

## 非目标与验收边界

不在眼镜内支付，不支持自动提交，不做无依据推荐，不增加持续后台监听。真实创建订单及取消等路径的完整验收仍独立记录，不能将Mock测试当成真实交易通过。

最初PRD采用Node代理、计划TTS及其他扩展形态；当前基线已演进为设备直连、无TTS。本文件按当前源码校准，历史资料入口见[来源说明](PROVENANCE.md)。
